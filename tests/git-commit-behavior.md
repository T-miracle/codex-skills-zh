# Git 提交行为回归案例

修改 `git-commit` 的分组或信息规则后，用以下案例人工评估输出。将“输入”与 Skill 交给评估者，再按预期核对；接受语义等价的表达，不要求复现固定措辞。这里仅生成提交方案和信息草稿，不执行 Git 操作。

`verify.ps1` 验证项目结构与调用用例，不自动运行这些行为案例。

## 1. 已有功能的一轮完善

输入：检查记录台账本轮主要完善详情卡片展示，同时默认每页 20 条、修复固定列遮挡及翻页滚动位置。这些修改共同改善台账浏览体验，均已验收，无独立发布时间要求；几个修复根因不同，技术上可分别撤销。共享详情组件也供智慧巡检台账使用。项目使用中文，请整理提交方案和信息草稿。

预期：一个提交；单行标题先概括详情展示，再简要提及相关调整，中文标点自然。无需穷举所有小改动或添加正文。不按四项行为拆成四次提交，也不因主功能已存在而逐个拆分修复。验证范围仍包含相关小改动和共享组件的调用方。

## 2. 同一页面中的独立交付

输入：同一台账页面修改了详情布局和权限规则。布局已经验收并计划今天上线，权限规则有单独的验收标准，尚待确认并计划下周发布。两者无代码依赖。请给出提交方案和信息草稿，不执行提交。

预期：分为两个提交，说明分别验收、发布的具体收益；不因同一页面而合并，不把布局依赖于尚未确认的权限改动。

## 3. 配套修正与无关旧缺陷

输入：尚未提交的新导出功能包含取消按钮、开发中修正的文件名错误及测试；另外顺手修复了与导出无关的登录超时缺陷，两者可独立验收。请整理提交草稿。

预期：导出功能及相关修正、测试归为一个 `feat`；登录缺陷另为一个 `fix`。不为取消按钮、文件名修正和测试分别创建提交。

## 4. 英文的单行主次表达

输入：The project uses English commit messages. This delivery corrects the ledger detail layout and also fixes overlapping fixed columns and incorrect scroll positions after pagination. The changes were accepted together. Draft the commit message only; there are no breaking changes or issue references.

预期：一个单行 `fix` 草稿，先主要变化，再用自然的英文标点或连词连接小修复。省略无必要的 body/footer，保留协议前缀中的 `: `；不套用中文顿号或机械重复 “fix”。

## 5. 必要的多行补充

输入：已有订单导出功能修复了金额精度丢失。为此 CSV 的金额字段改成十进制字符串，旧消费者按数值类型解析会失败；消费者需要改用十进制字符串解析。项目使用中文且没有额外提交模板要求，请写提交信息草稿。

预期：标题简洁、类型符合修复意图，并标记破坏性变更；用必要的补充说明记录受影响的字段和消费者迁移方法。不能因偏好单行而隐去兼容性影响，也不需要添加普通小改动清单。

## 6. 明确指定范围与仓库格式

输入：用户仅要求为已暂存的详情布局修复写提交信息；同一页面还有未暂存的滚动修复。仓库要求英文标题最多 72 个字符，body 必须说明修改原因。已确认布局错误来自窄屏固定宽度导致的内容遮挡。请提供草稿，不操作 Git。

预期：只描述已暂存的布局修复，服从仓库语言、长度和 body 要求。不能为了凑齐同一交付而纳入未暂存内容，不能把单行默认值凌驾于仓库模板，也不能执行提交或改写历史。
