# 技能机制（Skill mechanics）

这是 [`writing-for-agents`](SKILL.md) 中技能特有的分支：当文档是技能时，frontmatter、调用方式选择和路由技能有哪些不同。其他写作原则都在 `SKILL.md` 的通用参考中。

## 调用方式（Invocation）

两种选择，在两种负载之间权衡：

- **模型调用（model-invoked）**的技能保留 `description`，智能体可以自主触发，其他技能也能调用。人类仍可输入名称：模型调用始终_包含（includes）_用户调用；description 只会增加智能体发现能力，不会移除人类入口。description 是技能的顶层上下文指针，必须始终加载：用永久上下文负载换取可发现性。全部内容都是参考的模型调用技能，也可作为共享参考的唯一归属：其他技能可以调用，所以多个技能需要的参考能够集中存放。机制：省略 `disable-model-invocation`，并编写面向模型、涵盖触发分支的描述；`SKILL.md` 的指针写作规则全部适用。
- **用户调用（user-invoked）**的技能让 description 离开智能体可触达范围：只有人类输入名称才能调用，其他技能也不能调用。上下文负载为零，但需要认知负载：人类就是必须记住它存在的索引。机制：设置 `disable-model-invocation: true`；`description` 面向人类，仅用一行概括，不再列出触发条件。

只有智能体必须自主读取，或另一个技能必须调用时，才选择模型调用。如果始终手动触发，就设为用户调用，避免上下文负载。

两个用户调用技能都需要的共享参考不能归属其中任何一个：没有模型可见描述，它们无法互相触发。应把它放到技能系统之外的普通文件中，作为任何技能都能指向的外部参考。

## 按调用方式拆分（Splitting by invocation）

这是拆分的调用维度，顺序维度位于 `SKILL.md`：存在一个应独立触发的不同引导词，而且你确实在提示词中使用它，或另一个技能必须读取时，才拆出模型调用技能。新描述始终加载，需要上下文负载，所以独立入口必须有足够价值。

## 路由技能（Router skills）

当用户调用技能多到无法记住时，累计认知负载可由一个**路由技能（router skill）**缓解：用一个用户调用技能列出其他技能及使用场景，让人类只需记住一个入口。它只能提示，不能触发其他用户调用技能：它们没有模型可见描述，只有人类才能调用。
