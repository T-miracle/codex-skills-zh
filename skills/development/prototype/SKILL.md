# 原型（Prototype）

原型是**用于回答某个问题、之后即可丢弃的代码（throwaway code）**。问题决定原型的形态。

## 选择分支

根据用户提示、周边代码，或者在用户在线时直接询问，确定需要回答的是哪一种问题：

- **“这个逻辑或状态模型（logic/state model）合理吗？”** → [LOGIC.md](LOGIC.md)。构建可分享的单文件 HTML（自由操作按钮，加上分标签的引导演练），让非开发者也能操作状态机（state machine），体验那些难以在纸面上推理的情形。
- **“它应该是什么样子？”** → [UI.md](UI.md)。在单个路由上生成若干截然不同的 UI 变体（variations），并可通过 URL 查询参数和底部浮动栏切换。

两个分支会产生截然不同的制品：选错分支会浪费整个原型。如果问题确实含糊且无法联系用户，默认选择更符合周边代码的分支（后端模块 → 逻辑；页面或组件 → UI），并在原型顶部说明这一假设。

## 两个分支共同适用的规则

1. **从第一天起就把它视为一次性代码，并明确标注。**将原型代码放在它真正会被使用的位置附近（即所模拟模块或页面的旁边），让上下文一目了然；但命名必须使普通读者也能看出这是原型而非生产代码。对于一次性 UI 路由，遵循项目已有的路由约定；不要发明新的顶层结构。
2. **轻松运行。**UI 原型通过项目任务运行器中的一条命令启动：`pnpm <name>`、`python <path>`、`bun <path>` 等。逻辑演示则是双击即可打开的单个 HTML 文件。两种形态都应让用户无需思考就能启动。
3. **默认不持久化（no persistence）。**状态保存在内存中。持久化应是原型要_验证_的对象，而不是原型所依赖的条件。如果问题明确涉及数据库，就使用临时数据库，或者使用名称中清楚标有“PROTOTYPE, wipe me”的本地文件。
4. **省略润色。**不写测试；除了让原型能够_运行_所必需的处理外，不做错误处理；不做抽象。目标是快速获得认知。
5. **呈现状态。**每次操作后（逻辑分支）或每次切换变体时（UI 分支），打印或渲染完整的相关状态，让用户看清发生了什么变化。
6. **完成后留存。**把所有经验证的决策融入真实代码，然后将原型本身作为**一手来源（primary source）**留存：将其提交到 main 之外的一次性分支（throwaway branch），并在实现议题中留下指向该分支的上下文链接。还要在议题或提交中记录答案：结论以及它解决的问题。主分支只保留经验证的决策。
