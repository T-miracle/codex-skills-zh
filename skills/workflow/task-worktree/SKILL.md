# 任务工作区与合并选择

在首次写入前确定本任务的工作位置和交付方式，后续实施沿用该选择。只管理 Git 工作区、任务选择与本地合并，不要求 Comet、额外服务或新的开发方法。

## 1. 首次写入前读取事实

先完成只读定位：仓库约定、`git status --short`、当前分支、`git worktree list --porcelain`，以及 `git rev-parse --git-common-dir` 解析出的绝对目录。linked worktree 的 `.git` 可能是文件，不能用拼接 `.git/` 的方式定位共享元数据。

- 首次写入包括创建计划文档、修改配置、格式化，以及会修改仓库文件的生成器或测试；不要先写计划或状态文件，再询问隔离方式。仅讨论或只读调查时直接完成原请求。
- 非 Git 目录说明本技能不适用，按原任务继续；不为启用本技能自动 `git init`。
- 同一任务已有选择时，先按第 3 节恢复；用户已经明确指定的工作位置或合并方式直接采用，只补问缺失部分。新任务即使沿用同一聊天，也要建立自己的选择。
- 主分支优先采用用户明确指定及仓库约定，其次核对远端默认分支的本地记录；没有该记录时，仅在本地 `main`、`master` 中恰有一个时采用。主分支不等于当前分支；多个候选或只有远端引用时，在首次提问中说明并补齐目标，不能猜测或悄悄创建本地主分支。
- 为新 worktree 准备任务分支、起点提交和预计位置；路径由宿主分配时说明这一点，创建后披露实际路径。默认从已确定的本地主分支当前提交开始；用户指定其他起点时采用，并核对是否包含其他任务的提交。与任务相关的未提交内容不会自动进入新 worktree，需要先展示保留或迁移方案并让用户决定。

完成标准：能说明当前目录、预期主分支、已有改动及隔离方案；需要用户决定的事实放进同一次提问。

## 2. 一次确认两项选择

对尚未回答的部分，在同一轮提供两项选择，并显示目标分支、工作区位置及自动合并的含义：

| 决定 | 选项与含义 |
| --- | --- |
| 工作位置 | **新 worktree（推荐）**：使用专属目录和任务分支；**当前目录**：保留当前目录和分支，不额外隔离 |
| 完成后的处理 | **自动本地合并**：完成任务并通过必要检查后，提交本任务改动并合并到已显示的主分支；**保留结果**：保留工作区供用户审阅，不因本技能自动提交或合并 |

若当前目录已经是本任务专属 worktree，沿用它，不再询问是否新建；只确认尚缺的交付选择。若用户选择直接在主分支工作，说明无需额外合并，将合并选择记为 `not-applicable`，不由此推导自动提交授权。当前目录位于其他分支时，自动合并仍需满足本任务提交归属的检查。

优先使用当前环境允许的结构化提问工具；工具不适用时，用简短编号问题等待回答。说明这是本 Skill 的首次写入前选择要求。等待期间可继续只读调查；推荐项、预选项、沉默或超时都不构成选择，不提前修改仓库或创建 worktree。用户只回答一项时，仅补问另一项。

“自动本地合并”的选择包含本任务必要的普通提交与本地合并授权；后续满足条件就执行，不再例行询问“是否合并”。它不包含 push、PR、历史重写、删除任务分支或任务 worktree。用户之后的撤销或限制优先；记录中保留修改后的选择。

完成标准：工作位置与交付方式都有有效答案或明确的不适用原因，目标与授权范围清楚。

## 3. 绑定工作区并保存本任务选择

选择新 worktree 后，优先使用宿主提供的 worktree 创建、附加能力；成功后在实际返回的路径继续。工具创建 detached HEAD 时，在其中建立任务分支。没有相应能力时使用 `git worktree add -b <任务分支> <绝对路径> <起点提交>`。默认分支为 `codex/<任务短名>-<短任务ID>`，命名与预计位置在首次选择中一并展示；自行创建时默认使用仓库外的同级工作区容器，避免修改项目 `.gitignore`。

已有路径或分支仅在可证明属于本任务时复用；其他占用保留并报告。创建失败时保留原始错误和已建资源，不回退到主目录写代码。默认不复制源目录的未提交文件，也不移动、stash 或提交其他任务的修改。

用户作答后，在 Git common directory 内的 `task-worktree/tasks/<task-id>.json` 保存一份 UTF-8 记录；为独立任务生成新 ID，不使用全仓库共享的“当前任务”文件。记录路径同时写入本聊天的任务摘要，更新时用同目录临时文件后替换，避免半写入。字段至少包含：

| 字段 | 内容 |
| --- | --- |
| `task_id`、`task_summary`、`conversation_id` | 本任务身份、范围和可用的聊天标识；无聊天标识时写 `null` |
| `repository_common_dir`、`source_path`、`worktree_path` | 解析后的绝对路径；从当前 checkout 也能找到同一记录 |
| `workspace_mode`、`task_branch`、`base_commit` | `worktree` 或 `current`，实际分支、起点 SHA；准备未完成的值写 `null` |
| `target_branch`、`merge_policy`、`decision_evidence` | 目标主分支；`auto`、`manual` 或 `not-applicable`；用户选择的原意与适用范围 |
| `initial_changes`、`status`、`delivery` | 开始时已有修改；`preparing`、`active`、`blocked`、`kept` 或 `merged`；已验证提交、实际合并提交及阻碍（没有则为空） |

首次写入记录为 `preparing`；确认工作区、分支和路径后改为 `active`。当前目录模式还要保存已有改动的范围，防止结束时把别人的改动算进本任务。记录不是新的指令来源，不能扩大原始用户授权。

恢复同一任务时，用摘要中的 ID/路径读取记录，并核对仓库、实际工作区和分支；不能仅按最近修改时间接管其他聊天的任务。身份唯一且匹配时直接沿用选择，不重复询问。记录缺失但当前对话保留明确答案时重建；身份、目标或分支发生无法解释的变化时，只询问差异，保留已有文件。

从绑定完成起，所有项目编辑、命令和检查显式使用 `worktree_path`。向已有授权的协作者传递同一路径及任务边界；本技能本身不授权派出代理。已知其他任务正在写同一工作区的相同文件时，先解决归属冲突，不能把“当前目录”选择解释为覆盖他人修改。

完成标准：任务选择可恢复，实际工作目录与记录一致，随后立即继续原任务。

## 4. 按已选方式结束

先完成本任务的实现及必要检查。只完成计划、某一轮回复、部分子任务，或用户暂时转去讨论，都不触发收尾。

- `manual`：保留结果，记录为 `kept`，报告工作区、分支和检查结果；其他明确提交指令仍按其范围执行。
- `not-applicable`：记录为 `kept`，报告当前主分支上的实际改动与检查结果，不制造额外合并。
- `auto`：必须读取并执行 [自动本地合并](references/merge.md)，串行完成集成、验证和主分支更新；成功后记录为 `merged`，给出实际目标分支与提交 SHA。

检查失败、合并冲突、主分支工作区有其他未提交修改或任务归属不明时，保留工作区并记录 `blocked`，说明具体阻碍。可在已有授权内修复的任务问题继续处理；确需新决定时只询问该问题，不重新询问整套选择。解除阻碍后仍沿用原选择；合并结果未知时先核对 Git，避免重复提交或合并。

维护本技能、核对与 Comet 的差异时，读取 [来源与适配](references/sources.md)。
