# 自动本地合并

仅在本任务的 `merge_policy` 为 `auto`、原任务已完成且必要检查通过时读取执行。目标是把经过验证的本任务结果交付到已记录的本地主分支；用户已有选择足以授权下面的普通提交和本地合并。

## 准备任务提交

1. 核对实际目录、分支、用户最新选择和仓库提交规范。审查工作区、index、未跟踪文件及起点以来的提交，只暂存本任务文件或 hunks。已有 staged 内容或提交混入无关任务且无法分离时，保留并报告，不用 `git add .`、`git commit -a` 或改写历史掩盖归属问题。
2. 完成必要检查并复核 staged diff，再按仓库规范创建本任务所需的普通提交。可用的 `git-commit` Skill 可辅助提交，但不是依赖。提交 hook 失败时修复范围内问题并复查，不跳过 hook。记录实际任务提交 SHA；已提交且内容一致时直接复用。
3. 核对从目标分支合入会带入的全部提交和 diff，而不只看最后一个提交。包含未授权的其他分支历史时暂停交付。任务没有产生新改动且没有本任务待交付提交时，报告无变更，不制造空提交或合并。

## 串行集成

所有采用本技能的任务使用同一个 Git common directory 下的 `task-worktree/merge.lock`。在读取合并基线前，以文件系统**排他创建**取得锁，例如文件 API 的 `CreateNew` 或 `open(..., 'x')`；不能先检查不存在再普通写入。锁内容保存任务 ID、唯一 owner token、进程/会话标识与时间。

- 锁已存在时不触碰目标分支，也不删除锁；可继续独立只读工作，之后重试，或报告交付等待。时间久不代表锁失效；异常退出遗留的锁需核实原持有者已停止、没有 Git 操作进行后再恢复。
- 持锁覆盖下方基线读取、集成验证、主分支更新和结果核对。正常退出或阻塞时，在 `finally` 中核对 owner token，只释放本次成功获取的锁。
- 这是遵循本技能的任务之间的协作锁，不能阻止未采用此约定的进程写文件；因此更新主分支前仍要复查实际 Git 状态。

持锁后执行：

1. 读取目标分支最新 SHA 作为本次基线。通过 `git worktree list --porcelain` 定位检出该分支的目录，确认 index、跟踪文件和未跟踪文件均干净，没有进行中的 merge/rebase 等操作。已知该目录仍由另一个任务写入时等待其释放；不要 stash、reset、clean 或替别人提交。目标尚未检出时，可为本次交付创建一个专用目录检出它；Git 拒绝重复检出时重新读取事实，不强制绕过。
2. 先检查记录的任务提交是否已经是目标分支的祖先。确已交付时核对并记录实际结果，跳过重复合并；仅任务分支与目标同名、命令退出成功或聊天曾说“完成”都不是交付证据。
3. 用 `git worktree add --detach <绝对集成路径> <目标SHA>` 创建本任务拥有的临时集成 worktree，在其中合并固定的任务提交 SHA；集成期间不更新目标分支。默认保留已有历史，采用仓库允许的普通 merge，不重写任务分支。源任务与目标目录的未提交内容都不带入此工作区。
4. 有冲突时，保留集成工作区、冲突列表和任务分支，记录阻碍并暂停自动合并；不在主目录试错，也不整批选择 ours/theirs。无冲突时，对实际集成结果运行仓库要求且与改动相关的检查，确认工作区干净，记录通过验证的候选 SHA。检查失败则主分支保持原状，处理任务问题后重新集成验证。
5. 再次核对目标分支仍在记录的基线 SHA，目标目录仍干净且检出正确分支，并复查用户没有撤销合并选择。目标已推进时，从新的目标重新集成并验证，不沿用旧候选的通过结论；反复被外部写入打断时报告阻碍，避免无界重试。
6. 在目标目录用 `git merge --ff-only <已验证候选SHA>` 更新主分支。不能 fast-forward 时保留候选并重新核对，不自动改成强制更新。命令结果未知时先读取实际 HEAD 和状态，再决定是否还需要执行。
7. 核对目标 SHA 与验证候选一致，任务提交已是目标祖先，目标工作区干净；记录交付 SHA 和验证依据。若发现外部并发改动，报告实际状态，不以回滚或清理覆盖他人工作。仅满足交付条件才报告合并成功。

最后释放本任务的锁。成功且干净的临时集成/交付目录，可在核对路径和本次创建归属后用非强制 `git worktree remove` 清理；阻塞现场保留。任务 worktree 和任务分支默认保留，不执行 push、PR 或自动删除任务成果。
