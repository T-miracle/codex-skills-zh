# 阶段边界（Phase boundaries）

**阶段（phase）**是会话中的一块工作：追问、实现或 QA。这个定义有意保持模糊：当你觉得*“好，这部分做完了”*时，阶段就结束。

**阶段边界（phase boundary）**是两个阶段之间的间隙，也只有这里适合做上下文选择。阶段中途无需选择：继续，或把剩余工作拆给子代理。中途压缩会让智能体失去思路。

## 五种选项（The five options）

| 选项 | 作用 |
| --- | --- |
| **继续（Continue）** | 留在当前会话，完全没有上下文切换。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写出可移植 Markdown 文件，以它为种子在任何位置开启会话。 |
| **子代理（Subagent）** | 将任务发送到独立上下文窗口，得到报告。 |
| **`/compact`** | 压缩当前上下文，以摘要为种子开启后续会话。 |

## 决策树（The tree）

在边界处从上往下判断，第一个**是（yes）**决定分支。

**1. 能在当前会话继续吗？**两种情况应回答是：下一阶段需要本阶段作为**一手来源（primary source）**，或者剩余[智能区（smart zone）](https://www.aihero.dev/ai-coding-dictionary/smart-zone)足以容纳下一阶段，先进模型约为 150k tokens。追问后实现是典型情况：实现需要逐字推理，而非摘要。继续没有成本，也不会丢失信息，因此应首先考虑它。

**2. 当前上下文与接下来的工作无关吗？**本会话的探索、决策和死胡同是否全部可丢弃？如果是，使用 **`/clear`**。它耗时最少，释放整个窗口。使用 `/clear` 也不是终结：旧会话仍可恢复。

选错的代价不可逆。清空*相关的*上下文会丢失构建背后的**原因（why）**，重新阅读差异也无法找回。

**3. 需要交接吗？**`/handoff` 适用范围较窄，只有以下情况需要：

- 更换**执行工具（new harness）**，例如 Claude → Codex；
- 移到**新目录（new directory）**或仓库；
- 把工作交给**同事（colleague）**；
- 或在**阶段中途（mid-phase）**分出支线任务，同时保持当前工作。

这些就是全部适用条件。`/handoff` 提供的是**可移植性（portability）**：能够带走的文件。没有内容需要带走时，就不需要交接。

**4. 任务可以离席完成（AFK）吗？**范围是否足够明确，无需实时引导？如果是，将任务交给**子代理（subagent）**，保留当前会话。自动审查是典型场景：智能体读取差异并报告，执行期间不需要人类参与。

**5. 否则使用 `/compact`。**上下文仍相关、执行工具和目录相同，而且需要保持人在循环中时，决策树会落在这里，这也很常见。给它一条指令，例如 `/compact we're going to QA this area`，让摘要保留下一阶段所需信息。

`/compact` 是**兜底选项，而非第一选择（default, not the first reach）**。它在树底部，是因为前面四个问题对应的选择更便宜或更精确。直接从这里开始的失败模式是：新会话会对摘要压平的决策自信地作出错误判断。

## 一手与二手来源（Primary and secondary sources）

除**继续（Continue）**外，每项操作都将**一手来源（primary source）**转为**二手来源（secondary source）**：真实发生的会话被摘要替代。权衡形状始终相同：

| 来源 | 信息 | 噪声 | 可用空间 |
| --- | --- | --- | --- |
| 一手（Continue） | 完整 | 多 | 少 |
| 二手（`/compact`、`/handoff`） | 有损 | 少 | 多 |

因此第一个问题最先判断：只有留下来的成本高于收益时，才支付有损摘要的代价。

## 这些属于判断性决策（These are judgement calls）

问题并不客观，每个都涉及偏好，同一边界在不同日子可以选不同分支。价值在于到达边界时**按顺序（in order）**判断，而非工作中途判断。
